I have a good picture now. Here's what kyctrl is and how it fits together.

  What it is

  An AI Maintainer Assistant prototype for the Kyverno project (built for kyverno/kyverno#16665). It's a FastAPI service that listens to GitHub webhooks and autonomously handles two
  kinds of routine maintainer chores:

  1. Dependabot/Renovate PR auto-merge — reviews dependency-bump PRs and merges the safe ones
  2. Issue triage — classifies incoming issues, flags missing info, and moves them through a labeling state machine

  The core design principle (stated repeatedly in the code): merge/hold and label-transition decisions are deterministic policy, not LLM judgment calls. Plain Python decides what
  happens; the Claude Agent SDK is only used to explain the decision in a comment and to handle genuinely ambiguous edge cases (unparseable PR title, misfiled issue).

  Notable safety mechanisms

  - Two independent kill switches: enabled: false in .github/ai-maintainer.yaml (needs a PR) and the AI_MAINTAINER_ENABLED GitHub repo variable (instant, dashboard-togglable). Either
  one being off stops all action, and it's rechecked mid-run, not just at start.
  - Capability scoping: the model is never given tools it shouldn't have — e.g., the merge tool literally doesn't exist in the MCP server unless the rule engine already cleared the PR;
  the kill-switch toggle is never exposed to the model at all.
  - Sandboxed SDK calls: SandboxSettings restricts network access to just api.github.com and api.anthropic.com.
  - Full audit trail: every decision, the reasoning, cost, duration, and a revert command are logged to SQLite.
